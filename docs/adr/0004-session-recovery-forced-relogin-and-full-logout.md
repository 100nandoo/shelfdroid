# Session Recovery, Forced Re-Login, and Full Logout

ShelfDroid will treat silent token refresh, forced re-login, and full logout as different policies. When a request fails authentication, ShelfDroid will attempt session recovery once by refreshing tokens; if that fails, it will clear only the access token and refresh token, preserve local app data and cached content, and route the user into a forced re-login for the same user on the same Audiobookshelf server. Before rendering the forced re-login surface, ShelfDroid may re-read the server's current login configuration and must obey the current login methods instead of assuming that local username-password login is still valid. If the server no longer offers local login, ShelfDroid must not present a stale local-password recovery path. An explicit full logout from Settings is destructive only after the Audiobookshelf server accepts the remote logout request; if remote logout fails, ShelfDroid must cancel the full logout, keep the current session active, and surface the error. When full logout succeeds, ShelfDroid must clear local authentication state, local app data, cached content, and current playback in-process, then route to the plain login screen without restarting the app. The forced re-login screen may offer a confirmation-gated escape hatch into full logout for intentionally switching server or account, and that path must still perform destructive local cleanup and route to the plain login screen even when remote logout can no longer succeed because the refresh token is already gone.
