# Domain-oriented data-layer seams

ShelfDroid will replace the legacy `core.data.response` bucket with domain-oriented data-layer seams while keeping legacy names compiling during an expand-then-migrate transition. Public callers should depend on the repository set exposed from `core.data.library` (`LibraryRepository`, `LibraryItemRepository`, `PodcastEpisodeRepository`), `core.data.listening` (`ProgressRepository`, `BookmarkRepository`, `ListeningStatsRepository`), `core.data.users` (`UserRepository`), `core.data.tags` (`TagRepository`), and `core.data.podcastsourcefeed` (`PodcastSourceFeedRepository`). Internal single-source persistence and transport helpers stay behind those seams and use `*LocalDataSource` or `*RemoteDataSource` names whenever they become explicit. Screen repositories may depend directly on more than one public repository when that reflects the real domain seams, so Podcast- and player-related flows may use both `LibraryItemRepository` and `PodcastEpisodeRepository` instead of forcing all Library data reads through one facade. We are choosing this because the current package hides real ownership boundaries behind historical naming, makes it unclear which classes are intended seams, and encourages new features to couple to storage helpers instead of the repository that owns the domain concept.
